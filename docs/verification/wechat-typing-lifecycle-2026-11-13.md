# 微信输入状态覆盖完整任务

修复首条阶段消息后即关闭输入状态的问题。沿用服务已有 ReplyLifecycle：开始问答时启动，完整问答及正文发送返回时清理；不在 SendChunk 入口停止。每次成功发送文本后以容量为 1 的通知队列异步唤醒输入状态循环，避免客户端收到消息后清除提示；通知合并，重置 5 秒定时续期，不等待输入状态 HTTP 请求，不增加模型调用。

归属当前入站消息的正文发送失败时取消输入状态；同用户另一条命令回复失败不能误关正在进行的分析。整轮完成、问答失败、用户取消或通道停用仍通过原生命周期清理。在途开始请求先完成或被取消，再尝试 status=2；开始请求结果未知时也尝试清理，避免错误地遗留输入状态。所有输入请求仍有 3 秒超时，无票据或接口失败不阻塞正文发送。

回归用例先在旧实现复现失败，修复后发布分支 IM 全部竞态检查通过。覆盖阶段后及时恢复、5 秒续期、终稿后关闭、取消期间在途请求、首次开始结果未知、同用户命令交错、正文失败、通道及用户隔离、正文节流和输入超时。测试的并行事件记录用互斥锁保护，非生产竞态。

本次保留现有终稿分块、iLink 安全拒绝诊断、配置、模型提示、凭据及数据库；不重跑、不补发旧报告。未通过真实微信发送测试消息。手机端提示是否持续可见、取消是否及时关闭仍需实际验收；不将本次修复解释为 ret=-2 已解决。
