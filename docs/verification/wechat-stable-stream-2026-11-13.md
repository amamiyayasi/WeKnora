# 微信阶段实时输出修复

原实时配置已生效，但普通 Agent 轮次的用户可见阶段正文没有投递到微信。另有两处 Miko 业务验证仍限定 full，导致 stream 通道无法完成业务绑定。

按用户确认的 Octop 阶段实时语义，复用原生模型与工具轮次：工具轮确认后的普通正文通过已有 AgentProgress 事件投递，最终自然结束轮确认后提交正文。不修改模型提示，不为实时效果强制增加模型调用。思考只来自显式思考事件，工具名称和状态受通道开关控制；两者默认关闭。没有阶段正文且两个开关关闭时，仍可能只有最终回复。

对照公开源码：TencentCloud/Octop cd17e8d3551a22e6757f11e030879420243c089f 的 stream_project.py 在节点切换时投递 FLUSH；octop-gateway 224ed078ce20042fb5fa59240d6e3c7c34bcd67f 的 channel.py 在 FLUSH、完成时发送积累正文。它不承诺微信同一气泡逐字更新，也未在投递层强制新增模型调用；用户实际 Octop 实例版本尚未核实。

阶段正文与最终正文分别记录成功发送进度，重复阶段事件不重发；数据库保存完整最终回答。保留段落尾换行。原生已有最终合成路径开始发布后发生上下文溢出时不重新生成已发布正文，保留生成部分并走错误流程；其他通道的覆盖更新行为保留。

本地贯通测试使用真实 Agent 引擎：一次工具轮输出阶段正文，下一次原生最终轮等待阶段已发送才完成，断言恰好两次模型调用、最终回答完整保存且不重复阶段正文。另覆盖草稿过滤、未知发送结果不重试、取消、展示开关、Unicode 分段和溢出后不重新合成。

未向真实微信发送测试消息。手机端需验证阶段到达、输入状态和取消。此前 stream 扫码确认失败的业务绑定需重新扫码恢复原有身份及版本证明，不可手工绕过绑定校验。
